# 验证流水线（verify）

写完新文案后，起一个**干净的 subagent** 客观对比「新文案 vs 对标」，判断风格贴近度。

## 为什么用 subagent
主对话带着「怎么写的」全过程记忆，自我评价会偏心。干净 subagent 只拿到对标 + 新稿 + 一份维度清单，不带任何预设结论，结论更客观。

## 怎么起
用 Agent 工具起一个 `general-purpose` subagent，prompt 里只给三样：
1. 对标文案路径（**原文**，不是 DNA）。
2. 新文案路径。
3. 一份对比维度清单（见下）。

**不要**告诉它「新稿是用什么方法写的」「你觉得哪篇好」，否则就污染了客观性。也**不要**把主对话里已下的结论喂给它。

## 对比维度（喂给 subagent，要求逐项引原文证据）
1. 行文节奏 / 句长（短意群？一个意思一句？）
2. 开场方式（钩子 / 信任声明 / 引导）
3. 结构骨架（分层/分段过渡句是否点出核心矛盾）
4. 单段/单品结构（优势+短板+适合谁是否完整，缺点是否软化）
5. 参数/事实是否翻成体验（而不是只报数据）
6. 收口句式（如「适合……的人」）
7. 语气温度（夸张词 / 填充词 / 书面化程度）
8. 口头禅与固定句式
9. 结尾总结风格（决策框架 vs 空洞升华）
10. AI 味（连接词滥用 / 排比三连 / 书面长句 / 每段总起小结闭环）

## 输出
- 一句 verdict：新稿 vs 对标，贴近还是偏离。
- 3–5 条关键证据（每条引原文）。
- 注意：persona 名字若用户指定替换过（如署名换了号名），**不作为硬扣分项**，在 prompt 里说明。

## 交付
把 subagent 的 verdict **如实**转述给用户，不美化、不粉饰。若偏离严重，回到 write 步骤改，再验。
